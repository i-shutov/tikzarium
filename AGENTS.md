# TikZarium Studio — engineering instructions

## Latest owner priority correction — 2026-11-11: SCIENCE FIRST, DATA LAST

The full Multi-Engine Scientific Studio remains the principal product. The owner's subsequent instruction supersedes the delivery order in PR #173: **scientific graphics → UML → BPMN → engineering → chemistry and biology → animation → everything else → data, strictly last**. UML and BPMN are distinct acceptance stages within the second requested domain wave. Do not demote BPMN back into later engineering, put animation after the general extras, or start Data Figure in the scientific stage.

The single current [ROADMAP](docs/ROADMAP.md) uses stable domain IDs ST-SCI, ST-UML, ST-BPMN, ST-ENG, ST-CHEMBIO, ST-ANIM, ST-OTHER, ST-DATA. Earlier numbered ST0–ST8 schedules and the Graphviz-first vertical from PR #173 are historical. [Current execution plan](plans/2026-11-11_STUDIO_REBASE.md) replaces the earlier task ordering; read it with [PRODUCT_SPEC](docs/PRODUCT_SPEC.md) and [ARCHITECTURE](docs/ARCHITECTURE.md). Preserve historical evidence, do not rewrite it as new acceptance.

Shared Studio shell, design, documents, engine/build contracts and QA are enabling work INSIDE the current scientific delivery, not a preceding programme that delays scientific value. The first proposed additional scientific profile is Asymptote, followed by Typst/CeTZ, after explicit upstream verification. XeLaTeX/TikZ and PGFPlots are first-class. Graphviz/D2/Mermaid are no longer mandatory first backends; use them later only for the scoped domain or as a documented indispensable dependency, not to smuggle a general diagram product ahead of science.

**Data-last boundary:** preserve existing .dat/.csv resource handling, dependency hashes, formula/static-coordinate plots and all mandatory PGFPlots/SCI142/AI88 fixtures now. This is compatibility and scientific illustration, not permission to start a new data product. New tabular import UI, column mapping, cleaning/transformation/statistics, Data Figure, dashboards and Vega-Lite/Matplotlib/Gnuplot/Plotly product integrations belong to ST-DATA after ST-OTHER. Existing corpus MUSTs are not deferred merely because their native source reads a table.

Full Studio remains the goal, not an optional post-1.0 appendix. The earlier global TikZ-only feature ceiling stays superseded; a concrete release candidate still needs scoped freeze and actual GO. Do not reinterpret a priority change as implementation evidence, runtime PASS or permission to drop prior requirements.

## Product and architecture boundaries

1. Retain Rust/egui and the existing core/app/CLI/extensions. Evolve by tested vertical slices; do not replace the application with an unproved web shell, a universal graphics language or empty speculative crates.
2. A project can contain multiple figures and native source documents with assets/dependencies. Each editor view has an explicitly active document and revision. Source plus authoritative preview remain the normal workspace; focus views are deliberate choices. Linked publication composition is a separate document, not destructive conversion of sources. Data workspaces are delivered last, even though project files can already reference data resources.
3. Native formats remain authoritative: .tex/.tikz, .asy, .typ and later .dot/.d2/.mmd, UML sources, .bpmn/XML, JSON and domain formats as actually supported. A shared engine API does not imply a shared semantic AST. Derived object indices/handles are invalidated by source edits. No promise of arbitrary PDF/SVG-to-TikZ inversion or lossless cross-language conversion.
4. For supported edits, use minimal revision-checked patches and one reversible transaction. Preserve comments, unknown macros/fields, unrelated bytes, Unicode and CRLF. No-op Open/Save must not reformat source. When exact safe editing is unavailable, use explicit source-first/OPAQUE mode; it is not an accepted visual adapter.
5. Keep a versioned catalogue for tools, Inspector, completion and Russian F1/hover: native syntax, parameter types/units, allowed values, verified default versus editor preset, effects/limitations, example, dependencies, engine/version and manual locator. Never invent defaults; UNKNOWN is valid. Do not redistribute manuals in bulk.
6. Separate engine detected/version checked, dependencies installed, project-loaded, compatible, render available, help available, L3 operations and L4 round-trip scope. A successful render or a menu item does not establish visual editing support. A generic flowchart is not UML or BPMN acceptance; validate the specific domain's supported semantics.
7. Engine output is authoritative within its supported format. Interaction overlays and approximate handles must be labelled. Mathematical expressions, semantic constraints and engine layout remain with the appropriate engine unless an explicitly tested operation is implemented. GUI appearance never silently changes figure typography or colours.

## Runtime, privileges and trust — retained requirements

8. Local/offline operation with independently installed engines is the default. XeLaTeX/MiKTeX remains a first-class existing adapter; additional engines are explicit choices, never silent fallbacks. Do not bundle a second TeX distribution, auto-install packages, download runtime dependencies, enable shell escape, or change global TeX settings. Package activation is a shown, undoable source patch, not installation.
9. Support the user's existing Administrator account, including HIGH/elevated execution, with the actual privilege warning and trusted-document restriction. Do not force elevation or change UAC, registry, users, system fonts, RDP, drivers or MiKTeX. Unknown/SYSTEM contexts remain separately unsupported. No changes to FlowBridge, its runners/services/directories, or unrelated repositories.
10. External code is not made safe by a timeout or no-shell-escape. Python/Manim/SchemDraw and other executable sources require explicit trust policy. Do not execute them automatically on opening a project. Use direct argv process invocation, bounded logs/workers, child-process-tree cancellation, controlled working/output directories and honest isolation capabilities. Claim OS sandboxing/network restrictions only when actually enforced and tested. Renderers must not silently execute SVG scripts, load remote assets or accept unbounded images.
11. Optional remote services, including user-selected Kroki, are opt-in and must show the endpoint and data sent. No obligatory account, telemetry or cloud. Version/licence/platform/output claims for new engines are candidates requiring primary-source verification before implementation/distribution; they are not verified product capabilities.
12. Builds capture document revisions, dependency hashes, engine/options/version and relevant environment. Do not publish stale results over newer ones. Preserve last-good preview with an explicit stale marker. Exporting current output must reject stale data; a separately labelled historical export is a distinct explicit operation. Diagnostic navigation must identify the correct file, never apply an included-file line to another buffer.
13. Keep Unicode/formula/font-embedding checks and source/preview/export provenance. A zero exit code or successful PNG capture is insufficient. Never redistribute user font binaries.

## Scope, platforms and acceptance

14. All UX-F01…F14 remain required. UX quality precedes claiming large-scale visual-adapter acceptance; shell/editor/engine work may proceed together within the current scientific stage. Preserve the real 10k-line/1 MiB performance budget (p95 input-to-frame <=50 ms; first editable frame <=2 s) and 100k-line/10 MiB stress without input loss. CPU-only experiments do not prove native p95.
15. Preserve SCI142 = 100 AK + 42 Sarov and its 103 requirements, separately from AI88 = 88 examples / 35 specialised packages / 23 libraries / 13 skill contracts. Do not add AK100 to 142 again. Preserve three explicit LuaLaTeX cases 65/68/86 and the other 85 XeLaTeX cases. PGFPlots SC3/AT4 remains mandatory in ST-SCI. AI88 domain work follows the new order without deleting cases or changing their original IDs/criteria; cross-domain classification and deferrals must be recorded, not inferred as PASS.
16. Windows 10 Pro x64 is the primary user desktop; the existing Windows Server 2025 is a separate integration/GUI environment. Keep macOS ARM M1/M4 and Linux architecture/CI, with independent native qualification for their releases. Never equate hosted Windows Server 2022, personal Server 2025 or Linux/Xvfb with Win10 acceptance. Do not assume a direct desktop channel exists without a current successful read-only probe.
17. Retain W0–W4, independent original evidence, actual W2b/W3, real IME and 100/125/200% = 96/120/192 DPI for the relevant candidate. Legacy passes retain their exact SHA/environment and do not transfer to a new layout/binary. [Windows acceptance ledger](docs/WINDOWS_1_0_RELEASE_CONTROL_RU.md) remains the evidence source.
18. No version bump, stable tag, publication or rebranding of the existing RC as a completed Studio from this documentation change. Domain milestones are not semantic release versions. Freeze a concrete candidate scope and require its actual GO. Intermediate scientific builds may ship only with their truthful scope; they do not fulfil the whole Studio programme.

## Execution and priority discipline

Only ST-SCI and the enabling foundation are the current implementation priority. Later product stages are QUEUED_BY_PRIORITY. A prerequisite must name a current scientific scenario/requirement that needs it; broad architecture, general diagrams, Publication Studio or data work must not become hidden gates before scientific graphics. After the scoped stage is independently accepted, activate the next domain; changing order or reducing an existing MUST requires an explicit owner decision.

Read fresh main and active PR heads. Use isolated branches and exact-head leases. Integrate meaningful code+tests+plan/insights blocks; never let workers concurrently own main.rs or reimplement shared contracts. Prefer capable junior models for bounded implementation/test/catalogue tasks, with independent review and one integrator. Record the actually launched model/session/task ID. A written issue or failed agent assignment is not a running subagent; unavailable delegation must be reported honestly.

Status vocabulary: PLANNED, QUEUED_BY_PRIORITY, IMPLEMENTED_NOT_VERIFIED, UNIT_EVENT, HOSTED_GUI, NATIVE_PLATFORM, INDEPENDENTLY_ACCEPTED, BLOCKED, NOT_RUN. Acceptance is per operation, engine version and platform, not an aggregate engine-count percentage. Save commit/PR, original logs/artifacts and one next executable task at every substantial checkpoint.
