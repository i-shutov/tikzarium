# Назначение и границы

## Назначение

Создайте поддержку 142 научных рисунков через **редактирование конструкций исходного TikZ**. Каждый инструмент должен иметь проверенную грамматику, свойства, правила правки и тесты. Не создавайте новую математическую систему или графический движок. TikZ, PGF и PGFPlots выполняют вычисления и окончательную отрисовку.

Пользователь должен выполнить один цикл без ручной правки кода, если конструкция поддерживается адаптером:

1. Откройте один рисунок.
2. Выберите линию, график, узел, заливку или другой объект.
3. Измените свойство через инспектор.
4. Убедитесь, что изменена только соответствующая команда исходника.
5. Постройте PDF внешним XeLaTeX.
6. Отмените правку. Проверьте возврат исходного файла.

Если адаптер не может доказать, какой диапазон исходника отвечает объекту, редактор должен отказать в визуальной правке. При этом текстовый редактор исходника продолжает работать.

## Не входят в область работ

- Одновременное открытие нескольких активных рисунков в одном сеансе.
- Галерея рисунков, многофигурное оглавление, массовые правки.
- Импорт Sarov `main.tex` как редактируемой композиции из 42 рисунков. Подготовка 42 отдельных тестовых файлов выполняется вне GUI.
- Вызовы Gnuplot, его графический интерфейс, чтение его временных `.table`.
- Выполнение пользовательского TeX-кода в Rust для оценки выражений.
- Полный парсер TeX с раскрытием произвольных макросов.
- Реверс-инжиниринг PDF в команды TikZ.
- Автоматическая установка MiKTeX, TeX Live, шрифтов и внешних пакетов.
- Запуск произвольных сторонних DLL, dylib, WASM-плагинов.

## Термины и статусы

| Термин | Значение |
|---|---|
| Рисунок | Один `.tex`/`.tikz` и его локальные зависимости |
| Исходник | Авторитетный текст TikZ/TeX в кодировке UTF-8 |
| Адаптер | Встроенный модуль распознавания и изменения определённой конструкции |
| Экземпляр | Распознанная конструкция, её диапазон байтов и свойства |
| Диапазон | Полуоткрытый интервал байтов UTF-8 в одном исходнике |
| Правка | Один проверенный `SourcePatch` и один шаг Undo |
| Предпросмотр | PDF последней успешной сборки или временный маркер на холсте |
| OPAQUE | Система не может доказать безопасное визуальное редактирование |
| L0 | Состав исходников и контрольные суммы |
| L1 | Фактическая компиляция внешним TeX |
| L2 | Корректное распознавание и описание конструкции |
| L3 | Реальная GUI-правка, PDF, Undo, сохранение соседнего кода |
| L4 | Предметный физический или геометрический инвариант |

Уровни L0–L4 независимы. Успешная компиляция L1 не означает L2 и L3. Выполненная ручная научная проверка одного рисунка не распространяется на остальные.

# Архитектура расширений

## OneFigureSession

`OneFigureSession` — новая внутренняя модель состояния. Она не заменяет существующий `Document`. Она хранит только выбранный рисунок, текущую ревизию, привязки распознанных команд и состояние сборки.

```rust
struct OneFigureSession {
    document: Document,
    revision: u64,
    selected: Option<InstanceId>,
    recognized: Vec<RecognizedInstance>,
    dependency_snapshot: ProjectDependencySnapshot,
    pending_build: Option<BuildEpoch>,
    preview_state: PreviewState,
}
```

Представленная структура — **проектируемый контракт**, а не готовый Rust API. Не создавайте второй источник текста. При ручной правке увеличьте ревизию. Удалите устаревшие экземпляры. Перестройте только нужные диапазоны распознавания.

## Контракт адаптера

Разделите распознавание, выдачу свойств и планирование правки. Планирование не должно изменять файл.

```rust
trait NativeTikzAdapter: Send + Sync {
    fn id(&self) -> &'static str;
    fn recognize(&self, source: &SourceView,
                 env: &FigureEnvironment) -> Vec<RecognizedInstance>;
    fn properties(&self, instance: &RecognizedInstance)
                  -> Vec<PropertyDescriptor>;
    fn plan_edit(&self, request: &EditRequest)
                 -> Result<SourcePatch, EditRefusal>;
    fn requirements(&self) -> AdapterRequirements;
}
```

`SourceView` возвращает текст, ревизию, идентификатор файла и диапазоны безопасного разбора. `RecognizedInstance` возвращает ID адаптера, диапазон UTF-8, тип, свойства и точность распознавания. `EditRequest` содержит исходный диапазон, старое значение, новое значение и исходную ревизию. `SourcePatch` сохраняет контракт существующего продукта. При несовпадении значения или ревизии адаптер возвращает отказ.

**Запрет:** адаптер не вызывает XeLaTeX, не открывает сетевые соединения, не пишет файлов и не исправляет произвольный текст вокруг своей конструкции. Все действия записи проходят через одну проверяемую транзакцию.

## Алгоритм распознавания

Реализуйте ограниченный лексический разбор. Он должен распознавать команды из явного перечня. Он не должен раскрывать произвольный TeX.

1. Прочитайте неизменный снимок UTF-8.
2. Найдите известные команды: `\draw`, `\path`, `\node`, `\coordinate`, `\begin{axis}`, `\addplot`, `\pic`, `\dimline` и другие поддержанные конструкции.
3. Учитывайте сбалансированные группы `{...}` и `[...]`, экранированный `%`, комментарии и математические группы.
4. Сохраните диапазон байтов каждой команды.
5. Определите простые литеральные ключи. Отдельно обозначьте выражения, имена координат и неопределённые макросы.
6. Передайте распознанный экземпляр одному специализированному адаптеру.
7. Верните `OPAQUE`, если синтаксис выходит за подтверждённую грамматику.

Не допускайте скрытой нормализации пробелов и переносов строк. Не удаляйте комментарии в пользовательских файлах. Очищенные файлы Sarov служат только тестовыми образцами.

## Точечная правка

Используйте существующие `SourceTarget` и `SourcePatch`. Вычисляйте кратчайший изменённый диапазон. Перед применением сравните старый текст и ревизию. При конфликте не вносите часть изменения.

**Пример:** пользователь изменил `samples=150` на `samples=180` в одном `\addplot`. Измените только значение `150`. Не перестраивайте весь `axis`. Не переставляйте соседние ключи. Не раскрывайте пользовательскую функцию `gauss`.

**Проверка:** после одного действия Undo должен восстановить исходный SHA-256 файла. Все `.dat`, макросы и неизвестные блоки должны сохранить исходные SHA-256.

## Управление зависимостями

Один активный рисунок может ссылаться на локальные данные. `AK-F6_4` и `AK-F6_5` подключают `optics-common.tex`. `AK-F14_3`, `AK-F15_1` и `AK-F21_2` читают данные `plot file`. Это не другие активные рисунки.

Используйте существующие `BuildService` и `ProjectDependencySnapshot`. Отслеживайте исходник, локальные `.tex`, `.dat` и ресурсные файлы. Применяйте хэш каждого входа для определения актуальности PDF. Отдельно отмечайте зависимости TeX Live/MiKTeX, которые находятся вне корня проекта. Не объявляйте их локально проверенными.

# Семейства адаптеров

## A. Базовая геометрия и путь

**Назначение:** поддержать исходные команды TikZ, а не рисовать независимые объекты. Адаптер использует доступный набор команд `\draw`, `\path`, `\fill`, `\clip`, `\node`, `\coordinate`.

**Вход:** диапазон команды и стиль на момент распознавания. **Свойства:** цвет, толщина линии, штриховка, наконечник, видимость, координата, размер, anchor. **Выход:** план точечной правки или обоснованный отказ.

Разделите простые и вычисляемые координаты. Для пары литералов `(2,3)` можно изменить числовой компонент. Для `($(A)!0.5!(B)$)` разрешите только документированную правку исходного коэффициента. Не вычисляйте экранный результат в Rust как авторитетную координату.

Отдельно распознавайте `--`, `.. controls ... ..`, `rectangle`, `circle`, `ellipse`, `arc`, `cycle`, `++`, `+(...)`, ключи `shift`, `rotate`, `scale`. Если путь содержит неизвестный макрос, не изменяйте геометрию этого участка визуальным перетаскиванием.

**Приёмка:** базовые шесть инструментов продолжают проходить прежние тесты N1. Дополнительно проверены arcs/ellipse, относительные координаты, области scope и сохранение порядка операций. Испытания применяют настоящие исходные команды, а не копирование текста в буфер.

## B. PGFPlots: оси и ряды

**Назначение:** пользователь изменяет существующий график через свойства. PGFPlots строит форму графика в PDF.

**Модель:** распознанный `axis` содержит локальные серии `\addplot` и ссылки на имена путей. Не храните вторую независимую таблицу точек, которая стала бы источником истины. Серия хранит только ссылку на исходный диапазон и параметры, которые можно доказанно изменить.

**Поддержка первого вертикального сценария:** `\begin{axis}[...]`, `\addplot[...]{...}`, `domain`, `samples`, `xmin/xmax`, `ymin/ymax`, `width`, `height`, `mark`, `line width`, `color`, `xlabel`, `ylabel`, `xtick`, `ytick`, `clip`. Сохраните `\pgfplotsset{compat=1.17}` из Sarov. При неизвестной версии пакета оставьте статус проверки неопределённым.

**Поддержка второго сценария:** несколько серий с независимыми формулами. При изменении одной серии сохраните остальные серии, их порядок и связанные имена `name path`. Не переписывайте серию целиком, если пользователь изменил только `domain`.

**Поддержка третьего сценария:** `plot coordinates` и числовые таблицы. Не округляйте входные значения. Если точка содержит выражение или макрос, покажите его в свойствах как исходный текст.

**Отдельная особенность:** нативный TikZ `plot (\x,{...})` не является `\addplot`. Используйте два разных адаптера. Оба используют PGF Math для вычислений. `SV-040` не должен запускать внешний вычислитель.

**Приёмка:** `SV-001`, `SV-003`, `SV-009`, `SV-022`, `SV-029`, `SV-040`, `SV-042`. Для каждого примера выполните правку ключа, PDF и возврат исходного SHA-256.

## C. Именованные пути, пересечения и заливки

**Назначение:** сохранить ссылки между объектами. Путь с `name path=A` может использоваться в другой команде. Пересечение `intersection-1` зависит от этих путей. Заливка `fill between` также зависит от двух именованных кривых.

Не изменяйте вычисленную точку пересечения как свободную экранную координату. Предоставьте редактирование исходных путей и параметров вычисления. После правки запустите XeLaTeX. При изменении имени пути обновляйте ссылки только через отдельную проверенную транзакцию; до появления такого адаптера сделайте поле имени доступным только для чтения.

Порядок слоёв, `soft clip`, `\clip`, `patterns` и `patterns.meta` влияет на результат. Сохраняйте исходный порядок операций. Не переносите заливку в другой слой для упрощения GUI. Не превращайте паттерн в растровую текстуру.

**Приёмка:** `SV-006`, `SV-007`, `SV-010`, `SV-027`, `SV-028`, `SV-039`. Проверьте названия путей, пересечения и ограничения заливки. При отсутствии доказанной связи адаптер обязан вернуть `OPAQUE`.

## D. Углы, размерные линии и формы

Адаптер `angles` изменяет параметры `\pic` и сохраняет ссылки на исходные вершины. Адаптер `tikz-dimline` изменяет размерные линии. Сохраните крайние точки, выносные линии, наконечники и положение подписи. Не создавайте визуально похожую произвольную стрелку вместо размерной линии.

Адаптеры `shapes.geometric` и `shapes.arrows` должны сохранять имя формы, свойства узла и anchors. Если форма из пакета не поддержана, показывайте PDF и исходник, но не выдавайте ложные управляющие маркеры.

**Приёмка:** `SV-005`, `SV-035`, `SV-036`, `SV-038`. Проверка включает F1, доступность свойства, SourcePatch, PDF и Undo.

## E. Макросы, циклы и PGF Math

Сохраняйте определения `\def`, `\newcommand`, `\pgfmathsetmacro`, `\pgfmathdeclarefunction`, `\tikzset` без принудительного раскрытия. Интерфейс может разрешить изменение известного литерального аргумента. Он не должен изменять результат вычисления через запись новой координаты.

Для простого `\foreach` поддержите переменную цикла и литеральный список. Не разворачивайте цикл в множество самостоятельных команд. Вложенные циклы и вычисляемые множества могут оставаться доступными только в исходнике.

Для оптических схем `AK-F6_4` и `AK-F6_5` допускайте изменение входного параметра макроса. Пересчёт геометрии выполняет TeX. Обновляйте карту зависимостей, если параметр расположен в подключённом `optics-common.tex`.

**Приёмка:** `AK-F3_1`, `AK-F6_4`, `AK-F6_5`, `SV-042`, выбранные рисунки с `\foreach`. Нельзя получить PASS, если редактировалась экранная координата вместо формулы источника.

## F. Данные, шрифты и публикационное качество

Проверяйте существование и хэш всех локальных `.dat`. Не изменяйте точки файла данных при редактировании стиля. Сборка должна повторяться при изменении зависимости. Для одной активной фигуры используйте один снимок входных ресурсов. Подключаемые исходники могут быть открыты в текстовом редакторе для диагностики, но не должны становиться вторым активным холстом.

В документах используются `fontspec`, `unicode-math`, `polyglossia`, `Noto Sans`, `Noto Serif`, `STIX Two Math`, `Charis SIL`. Не включайте лицензионные файлы шрифтов в поставку. Определяйте доступность локально. Сборка с кодом 0 не гарантирует наличие всех глифов. Отдельно проверяйте `Missing character`, `pdffonts`, читаемость русских подписей и математических символов.

# Риски и решения

| Риск | Влияние | Действие |
|---|---|---|
| Неизвестный макрос меняет область действия | Повреждение исходника | Возвратите `OPAQUE` |
| Неверная привязка пересечения | Физически неправильный рисунок | Редактируйте только исходный путь |
| Несовместимая версия PGFPlots | Другие координаты и стили | Сохраняйте compat и версию |
| Отсутствует локальный `.dat` | Пустой график | Отметьте ошибку ресурса |
| Текст меняется после распознавания | Патч попадает в чужой диапазон | Проверяйте ревизию и старый текст |
| Изменился пользовательский шрифт | Неполный PDF | Отдельный glyph/font audit |
| Долгая формульная серия | Блокировка GUI | Выделите работу из UI-потока |
| Версия TeX меняет PDF | Ложный визуальный FAIL | Фиксируйте окружение и порог |
| Windows Server QA выдаёт SUCCESS | Ложный физический PASS | Проверяйте оригинальные PNG и HWND |
| Запуск TeX под HIGH Administrator | Выполнение недоверенного TeX | Покажите предупреждение; не называйте режим sandbox |
| Ложное сравнение PDF по хэшу | Разные метаданные PDF | Используйте страницу, растр, шрифты отдельно |

# Проверка комплекта и источники

## Воспроизводимость

Данный пакет создаёт самостоятельный тестовый вход. Запуск `qa/compile_suite.py` требует доступного внешнего XeLaTeX, установленных пакетов и шрифтов, упомянутых в исходниках. Содержимое пакета позволяет проверить SHA, запустить сборки и сопоставить результаты с 142 эталонными PDF без скачивания дополнительного материала рисунков.

## Основания архитектурного решения

- [Текущий исходный репозиторий Tikzarium](https://github.com/i-shutov/tikzarium).
- `AGENTS.md`, `docs/ARCHITECTURE.md` и `docs/PRODUCT_SPEC.md`.
- `docs/WINDOWS_1_0_RELEASE_CONTROL_RU.md` на зафиксированном Git SHA.
- `crates/tikzarium-extensions/src/primitives.rs` и `primitive_edit.rs`.
- `crates/tikzarium-extensions/src/project_imports.rs`.
- `crates/tikzarium-app/src/tikz_authoring.rs`, `tikz_canvas.rs` и `studio_ui.rs`.
- Оригинальный корпус AK-100 от 07.11.2026. Шифр источника находится в манифесте.
- Оригинальный Sarov `main.tex` и 42 отдельные подготовленные фигуры. Оба источника приведены в `QA_MANIFEST.json`.
- ГОСТ Р 58049-2017. В тексте использованы принципы УТР: прямой порядок слов, одно значение термина, однозначные требования, короткие команды и активный залог.

**Правило изменений:** если инженер выявил новый тип конструкции, добавьте новый ID требования, адаптер, положительный и отрицательный тест. Не объявляйте семейство поддержанным только по успешному XeLaTeX PDF.
