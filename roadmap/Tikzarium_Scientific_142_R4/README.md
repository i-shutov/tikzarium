# Tikzarium Scientific-142 — технический пакет R4

Дата: 8 ноября 2026 года. Формат: LaTeX/PDF, Markdown, CSV, JSON, исходные TikZ, PDF-эталоны и воспроизводимые тесты.

## 1. Назначение

Пакет содержит инженерное ТЗ, архитектуру расширения существующих Rust-модулей Tikzarium и план реализации. Тестовый корпус содержит **142 отдельных файла `figure.tex`**: 100 AK и 42 Sarov. Каждый файл задаёт один рисунок. Программа должна редактировать один рисунок в каждый момент времени.

Требования описаны в `docs/SCIENTIFIC_142_TRD_R4.pdf`. Полный редактируемый исходник документа: `docs/SCIENTIFIC_142_TRD_R4.tex`. Текст в Markdown доступен отдельно. Каталог `REQUIREMENTS.csv` содержит **103 нормативных требования**, а `BACKLOG.csv` — крупные задачи реализации.

## 2. Проверенные результаты

- L0: 142/142 — исходники, PDF и SHA-256 проверены.
- L1: 142/142 — внешний XeLaTeX завершился успешно; ровно одна страница на рисунок.
- L1-R: 142/142 — растры новой сборки совпали с сохранёнными PDF-эталонами при 72 dpi и одном рендерере PyMuPDF 1.26.7.
- 120 предупреждений `nullfont` обнаружено в 13 рисунках Sarov. Эти предупреждения сохранены в `evidence/`.
- L2: распознавание в Tikzarium — `NOT_RUN`.
- L3: инструментальное редактирование в GUI и Undo — `NOT_RUN`.
- L4: полная повторная научная приёмка — `NOT_RUN` / отдельные прежние проверки.

**Не делайте вывод о поддержке всех 142 рисунков в GUI по успешной сборке XeLaTeX.**

## 3. Структура

- `docs/` — основное инженерное ТЗ в LaTeX, PDF и Markdown.
- `fixtures/AK/F.../figure.tex` — 100 оригинальных исходников AK. Комментарии и код сохранены побайтово.
- `fixtures/AK/data/` — 74 локальных файла данных. Для двух оптических схем включён `optics-common.tex`.
- `fixtures/SR/SV-.../figure.tex` — 42 подготовленных одиночных Sarov-рисунка без комментариев.
- `references/AK/` и `references/SR/` — 142 эталонных PDF.
- `provenance/` — неизменённый сводный Sarov `main.tex`, оригиналы AK, реестр, контрольные суммы.
- `QA_MANIFEST.json` — SHA-256, зависимости, источник, изменения и статусы для каждого рисунка.
- `QA_MATRIX.csv` — матрица уровней L0–L4.
- `REQUIREMENTS.csv` — нормативные требования для задач разработки.
- `BACKLOG.csv` — крупные рабочие задачи.
- `qa/` — валидатор, фактическая сборка, проверка PDF и отрицательный тест.
- `evidence/` — результаты последней проверки, 142 лога, 142 консольных вывода и PDF.

## 4. Проверка

Установите Python 3.11 или новее, XeLaTeX, `pdfinfo`, пакеты TikZ/PGF/PGFPlots, `fontspec`, `unicode-math`, `polyglossia` и `tikz-dimline`. Нужны локально доступные Noto Serif, Noto Sans, STIX Two Math и Charis SIL. **Файлы шрифтов в архив не включены.**

Из корня распакованного пакета выполните:

```bash
python3 qa/validate_corpus.py --json
python3 qa/test_negative.py
python3 qa/compile_suite.py --output ./build-142 --jobs 4 --timeout 100
```

Для дополнительного растрового сравнения установите PyMuPDF и NumPy и выполните:

```bash
python3 qa/compare_reference.py --build ./build-142 --out ./raster-142
```

Для работы в `uv` установите временные зависимости: `uv run --with pymupdf --with numpy python qa/compare_reference.py --build ./build-142 --out ./raster-142`.

При запуске под MiKTeX скрипт определяет движок и добавляет `--disable-installer`. В обоих окружениях он отключает shell escape. Скрипты не запускают Gnuplot, не меняют настройки системы и не устанавливают пакеты.

## 5. Изменения исходников

AK-100 скопирован побайтово. Sarov-42 извлечён из переданного сводного файла. В подготовленных копиях удалены комментарии. `SV-040` использует встроенную PGF Math формулу вместо Gnuplot. В `SV-042` исправлены два вызова функции `gauss`. Исходный `main.tex` сохранён без изменений. Все нормализации записаны в манифесте.

## 6. Правила развития

Используйте исходники TikZ как источник истины. Применяйте `SourcePatch` с проверкой ревизии и Undo. Используйте внешнюю компиляцию XeLaTeX. Для непрозрачных макросов возвращайте `OPAQUE`. Не вводите отдельный CAD, CAS или графический рендерер. Не создавайте многофигурный GUI.

Scientific-142 — отдельный функциональный трек после текущей заморозки Windows 1.0. Текущую ветку GitHub этот пакет не изменяет.

## 7. Контроль качества

Каждый документ и файл имеет SHA-256 в `SHA256SUMS.txt`. При внесении правок пересоберите PDF и обновите соответствующие хэши. Файлы проверки результата не должны повышать статус L2/L3 без реального доказательства Tikzarium.
