# Папка проекта и проверка входных файлов сборки

Для рисунка с внешними ресурсами выберите папку, которая содержит и исходник,
и его данные. Например, при расположении `project/figures/figure.tex` и
`project/data/curve.dat` папкой проекта служит `project`. Относительные пути
в TeX по-прежнему разрешаются от каталога исходного файла: `../data/curve.dat`
не переписывается.

## В Studio

1. Откройте или сохраните исходный `.tex`.
2. На вкладке **Библиотеки** в разделе **Ресурсы проекта** нажмите
   **Выбрать папку проекта…** и укажите общий каталог.
3. Нажмите **Собрать PDF**. При необходимости откройте **Входные файлы сборки**
   или нажмите **Проверить файлы сборки**.
4. Экспортируйте подтверждённый актуальный PDF.

По умолчанию используется каталог исходника. Выбор общей папки явный: наличие
`..` в TeX не расширяет область проверки автоматически. Выбор действует для
открытого документа; открытие другого документа сбрасывает его к значению по
умолчанию. После смены папки требуется новая сборка. Кнопка **Папка исходника**
возвращает значение по умолчанию. Папка должна содержать открытый исходный файл.

## В CLI

```sh
tikzarium-cli build project/figures/figure.tex result.pdf \
  --project-root project --log build.log
```

Параметры `--project-root` и `--log` можно указывать в любом порядке. Повторение
параметра, неизвестный параметр или отсутствие значения — ошибка. Без
`--project-root` используется каталог исходника.

Если локальные входы не подтверждены, CLI возвращает код 5 и не изменяет PDF по
указанному выходному пути. Диагностика объясняет отказ. Ошибка папки проекта
отклоняется перед компиляцией. Обычные ошибки TeX по-прежнему сохраняются в логе.

## Что проверяется

Перед запуском компиляции рабочий поток снимает контрольные суммы файлов
выбранной папки. После завершения TeX фактически использованные локальные входы
определяются по `.fls` и сравниваются с этим начальным снимком. Поэтому первая
сборка уже может подтвердить обычные локальные ресурсы, включая пути,
раскрываемые TeX-макросами; для этого не требуется предыдущая сборка.

Изменившийся файл той же длины, новый вход, которого не было в начальном
снимке, исчезнувший файл, неполный recorder или неподдержанный путь не дают
права принять результат. Studio сохраняет предыдущий корректный PDF с пометкой
об устаревании. При отсутствии такого PDF новая неподтверждённая сборка не
становится доступной для экспорта. Перед экспортом файлы проверяются снова,
включая повторную проверку после системного диалога выбора файла.

Обход ограничен 4096 файлами, 16384 записями каталогов, 4096 каталогами и
глубиной 64. Лимиты чтения — 64 МиБ на файл и 256 МиБ на весь снимок; превышение
приводит к отказу в подтверждении. Список входов `.fls` ограничен 8 МиБ.
Отмена и тайм-аут учитываются во время обхода и чтения. Проверки не выполняются
при каждом кадре интерфейса.

## Границы подтверждения

- Это сравнение состояния до и после сборки. Изменение файла с последующим
  восстановлением прежних байтов между наблюдениями этим методом не выявляется.
  Снимок не является неизменяемой копией входов или защитой от недоверенного TeX.
- Внешние файлы TeX вне выбранной папки явно перечисляются как непроверенные.
  Проверка проекта не подтверждает неизменность всей TeX-установки.
- Символические ссылки внутри проекта пока не поддержаны для подтверждения
  входов. Системный псевдоним над корнем проекта, например `/var` на macOS,
  не считается ссылкой внутри проекта.
- Переполнение лимита или недоступный файл в начальном обходе делает снимок
  неполным. Выбирайте конкретную папку научного проекта.
- Для строгого соответствия байтам, прочитанным движком при произвольных
  конкурентных изменениях, нужен следующий контракт неизменяемых входов.
