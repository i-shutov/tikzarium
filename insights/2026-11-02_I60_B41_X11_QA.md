Дата: 2026-11-02.

## Подтверждённая база

- GitHub `main` `48447d5916fa190b3ca7312130bde45d695ffd16`; B41 PR #89 `e9bdd306f1009fa1f444e7d8948e16a48b6ce190`, app/src `5fa3b794c4711cd32c1b0f68a0ea00c7bf38657a`.
- B41 Rust UI реализует `show_inspector_action_bar_frame` с pinned Apply через уже существующий `Session::apply_parameters`. UNIT_EVENT проверяет production handler в SidePanel 260pt, но **не** настоящее X11 Save/Open/контекст Ctrl+Z.
- В предыдущих CI #89 три старых workflow падали на B40 source-tree SHA до запуска окна. От этого **не следует** ни PASS, ни FAIL B41-жестов.

## Новая независимая работа

- I60 workflow и Python X11-процесс не вмешиваются в Rust B, C-каталог, A MiKTeX или D старые скрипты; сохраняют PNG, GUI-clipboard paths, saved .tex, PDF, app log и manifest с SHA.
- Из ранее принятого B40 artifact `i47-b34-desktop-df590b...` вручную просмотрен `pointer-circle.png`: radius был в правом инспекторе рядом с x=1165, y=558; Undo около x=1140,y=68. **У B41 изменился action bar, y координат перенесён только как кандидат**, не утверждается проверенная геометрия.
- Для PNG-профиля I60 предварительно выбраны radius (1165,580), Apply (1190,96). Они не подтверждены B41 снимком. Если тест не попал в реальный TextEdit/Apply, это QA-coordinate failure до дополнительной приёмки.
- Чистые source-fixtures включают неизвестный `\\OpaqueLabel`, кириллицу и отдельный CRLF control. C metadata v2 при radius-правке меняет и видимую TikZ-команду, и payload маркера; сравнение должно учитывать обе операции, запрещая любые другие.
- Для PDF обязателен реальный GUI Build/Export с внешним Linux TeX Live XeLaTeX. Это **не** MiKTeX/Win10 и не гарантия точного совпадения координат guide.

При создании QA-ветки: unit и X11 workflow **NOT_RUN** до точного head CI. Ручной анализ нового B41 screenshot/PDF **NOT_RUN**. Физические Windows 10 и M1/M4 **NOT_RUN**. Не изменять #89, пока отдельный QA не даст доказательства.
