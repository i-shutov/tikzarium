# Переход на Tauri: находки и основания решений

Дата: 17.11.2026. Связанный план: [TAURI_PRIMARY_MIGRATION](../plans/2026-11-17_TAURI_PRIMARY_MIGRATION_RU.md).

## D01 — интерфейс выбран владельцем

Tauri является основным направлением разработки по прямому решению владельца. Предыдущее предложение снова выбирать между egui и Tauri отменено. Сохранение egui означает только сохранение истории/регрессий и проверенного научного кода. Нельзя превращать это в вторую конкурирующую реализацию пользовательских функций.

## D02 — два рубежа вместо потери CP09

Проверенный remote main = `0a9831404687296a5467f89e77e873de8cdc5137`. Текущая научная ветка CP09 = `c057fc3c0b350a1405bf1305b3780a2aa550e144`, её native evidence относится к `92a01f2a8d58718e4d1439b0343e9d0d03d6444d`. Tauri PR #191 = `23164a7bae5dd71766e726f5bce96c96c6e368fe`, основан на main, а не CP09.

Следствие: только тег на main не сохранил бы под понятным именем последние научные наработки. Поэтому создаются отдельные архивные теги CP09 и main-before-tauri. Нельзя обозначать их стабильным научным v1.0.0: CP09 имеет явно открытые платформенные/корпусные gates. Создание тегов требует проверки удалённых peeled SHA; до такой проверки статус PENDING.

## F01 — Tauri CI пока не исполняется

На Tauri SHA workflow находится в `apps/tikzarium-studio-tauri/ci/tauri-v2-studio.workflow.yml`, а не в `.github/workflows/`. README прямо предлагает копировать его туда для активации. Следовательно прежние общие Rust/egui CI results не доказывают сборку отдельного src-tauri workspace или TypeScript frontend.

Решение: активный ограниченный workflow с раздельными frontend test/typecheck/build и Rust Tauri gates; первые отказы сохраняются. Не делать вывод «полноценная работающая реализация» по размеру App.tsx или наличию 9 команд в README.

## F02 — зависимостям нужна отдельная воспроизводимость

package.json использует диапазоны версий, а изолированный Rust workspace имеет собственное разрешение зависимостей. Неизменный корневой Cargo.lock не означает закреплённую Tauri-сборку. Необходимо проверить фактическое наличие требуемых версий, получить package-lock и Cargo.lock для приложения и перейти к npm ci / cargo --locked. На этой стадии работоспособность/ошибочность конкретных версий ещё НЕ проверена.

## F03 — native и browser-preview не равнозначны

В ветке есть двухрежимный tauriNativeBridge. Его native вызовы, browser fallback, соответствие типам Rust и настоящий запуск XeLaTeX требуют проверки исходников и выполнения. Визуально похожий PDF preview не заменяет внешний PDF и не переносит prior CP09 acceptance. Документы и Guide обязаны указывать режим.

## D03 — интеграция кода и выпуск — разные события

Владелец разрешил встроить Tauri в main и продолжать там разработку. Это разрешение на development-интеграцию, не доказательство завершённости всех инструментов, безопасности или Win10/IME/DPI. Не блокировать сам переход повторным обсуждением выбора оболочки; при этом сохранять дефекты, результаты проверок и честную release readiness.

CP09 scientific descriptors/patches переносить в общий Rust слой по операциям; не сливать целиком старый GUI ради формального наследования тестов. PR #190 отдельно сравнить с manual_anchors, уже добавленным Tauri: одна каноническая реализация, не два расходящихся каталога.

## D04 — делегирование без вымышленных запусков

Доступный launcher младших агентов в этой сессии отсутствует. Поиск доступных подключений не дал работающего launcher; локального Codex CLI также нет. Пакеты J1–J4/R1 описаны в plans, статус NOT_LAUNCHED. Основной исполнитель выполняет доступную интеграцию и проверку; его результаты не называются независимой агентной приёмкой.

Локальный контейнер не имеет доступа к github.com по DNS; попытка git clone завершилась `Could not resolve host: github.com`. Доступ через подключённый GitHub работает. Поэтому удалённые изменения выполняются через проверенные GitHub операции, сборки — на ограниченном GitHub-hosted CI. Не выдавать CI за локальный Rust запуск или пользовательскую Windows-машину.

## Открытые вопросы для проверки, не подтверждённые дефекты

- Совпадают ли аргументы/результаты всех tz_* команд между TypeScript и Rust?
- Собираются ли path-зависимости core/extensions из текущего main с Tauri?
- Сохраняются ли source bytes, CRLF, Unicode и revision fences на всех действиях, включая cancel/external edits?
- Отменяет ли cancel дерево реального процесса, и не публикует ли поздний build stale PDF?
- Ограничены ли capabilities/CSP и remote content, отсутствуют ли скрытые engine/runtime installs?
- Привязаны ли текущие default/source/manual значения к конкретным upstream-источникам, а не к демонстрационным данным?
