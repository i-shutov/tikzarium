# Tauri — основной интерфейс TikZ Scientific Studio

Дата решения: 17.11.2026. Статус первоначальной записи: IN_PROGRESS.

## 1. Решение владельца, не вариант для повторного выбора

Владелец прямо потребовал: зафиксировать текущий результат тегом, встроить ветку Tauri в main и продолжать разработку на Tauri. Выбор egui против Tauri повторно не обсуждается. Tauri + Rust становится основной поставляемой оболочкой; egui сохраняется временно как legacy-эталон, источник научных адаптеров и средство сравнения. Новые пользовательские функции не разрабатываются параллельно в двух оболочках без конкретной необходимости регрессии.

Находки, технические основания, риски, проверенные альтернативы и последствия решений записываются в insights. Там сохраняются воспроизводимые инженерные обоснования и доказательства, а не приватные внутренние рассуждения модели. plans содержит порядок работ, владельцев файлов, критерии завершения и фактический статус.

## 3. Порядок большого блока

3. Сохранить план и первичные findings отдельными коммитами. Не переносить большие архивы CP09 в git и не удалять исходную ветку.
4. Записать факт создания тегов и их объекты в insights. Никаких автоматических Release assets, установщиков или стабильного GO.

Завершение: оба удалённых тега действительно существуют и указывают на точные рубежи, история PR #189 и его artifacts сохранена.

### T1 — реальная интеграция Tauri в main

1. Зафиксировать новый owner override в AGENTS.md, PRODUCT_SPEC, ARCHITECTURE и ROADMAP: основная оболочка Tauri, legacy egui — только донор/регрессии.
2. Встроить PR #191 с сохранением истории, не заменять main содержимым случайного архива, не выполнять force-push.
3. Слить последующие исправления/документы из интеграционной ветки после сверки ожидаемого head. Проверить, что main содержит исходный Tauri commit.
4. README должен вести к Tauri-командам и честно различать рабочий native режим и browser preview. Не объявлять demo/mock-режим реальным внешним XeLaTeX.
5. PR #190 не сливать целиком вслепую: сравнить уже дублированный manual_anchors и сохранить только нужные недублирующие изменения. PR #189 оставить донором CP09 до пооперационного переноса; не считать его автоматически принятым в новой оболочке.

Завершение: Tauri-код и актуальная инструкция находятся в main; сборочная готовность и платформенная приёмка описаны отдельно от факта merge.

### T2 — воспроизводимая сборочная база

1. Активировать реальный workflow в .github/workflows; прежний файл внутри apps/.../ci является только шаблоном.
2. Проверить package.json по фактическому npm registry, сохранить package-lock.json; штатный CI — npm ci, затем test, lint и production build как отдельные gates.
3. Проверить изолированный src-tauri workspace, версии Rust, системные WebKit-зависимости и локальные path-зависимости. Сохранить отдельный Cargo.lock; штатный Rust CI — --locked.
4. Linux и Windows — отдельные jobs. macOS ARM — следующая самостоятельная платформа, без переноса Linux PASS. CI Windows Server не называть Windows 10.
5. Сохранить ошибки первой сборки и recovery logs; не ослаблять lint/tests ради зелёного статуса. Избегать неограниченной установки и затрат: ограниченные timeout, workers, размер artifacts.
6. Core/CLI/egui regression gates не удалять. Шрифты и массивные PDF-мануалы не публиковать в artifacts.

Завершение: фиксированные зависимости, явно исполняемый CI, раздельные результаты frontend и native Rust; все блокеры перечислены с точными логами.

### T3 — IPC, документы и безопасность

1. Проверить все tz_* команды по фактической реализации, а не README. Сопоставить frontend call, Rust command, тип запроса/ответа, error model и тест.
2. Проверить capabilities/permissions/CSP. Не давать удалённым страницам доступ к native API. Не включать обходы политики, shell escape, скрытую установку TeX/WebView/runtime или изменение пользовательской ОС.
3. Document::load/save, revision/hash fences, внешние правки, путь с Unicode/пробелами, CRLF, точное no-op сохранение, атомарная запись и общий Undo/Redo.
4. Cancel должен отменять реальный процесс и дерево потомков; поздний build не подменяет более новую ревизию. current/stale/last-good/error/absent — разные состояния.
5. Build/export: внешний XeLaTeX, диагностика правильного файла, dependency closure, проверка stale export. Browser mock не может генерировать native PASS.

Завершение: минимальный рабочий native вертикальный сценарий с исходниками, логом движка, PDF, SHA и отрицательными тестами.

### T4 — перенос научного ядра CP09, не возвращение старой оболочки

1. Инвентаризировать source-owned Axis/AddPlot/GroupPlot/Table/NativePlot и shared Undo в CP09.
2. Извлечь подходящие чистые Rust-контракты в общий слой без egui-зависимостей. Не копировать тысячестрочный main.rs, не переписывать то же правило в TypeScript и Rust независимо.
3. Через IPC связать реальные выбор/черновик/Apply/Undo, F1 и новый source editor. Диапазоны UTF-8 bytes и JS UTF-16 преобразовывать явно, с тестами кириллицы, combining marks и emoji.
4. Повторить сначала один полный AT4 и SV-040, затем 17 AT4 / 27 V2 операций с независимыми ledgers. Original warning FAIL и атрибутированные clean-производные сохраняются раздельно.
5. Данные/формулы/порядок колонок/ошибки остаются авторским содержимым. OPAQUE режим — не принятый visual adapter.

Завершение: пооперационный parity ledger на Tauri, а не заявление о наследовании старых 609 тестов или GUI-приёмки.

### T5 — интерфейс и эргономика

Компактное верхнее меню и иконки; отдельная колонка номеров строк; отдельная сворачиваемая преамбула/шапка; сохранение фокуса, caret, scroll и undo при переключении Чертёж / Шапка / Весь .tex. Inspector рядом с редактируемым объектом, один понятный Apply. PDF-калька и canvas overlay маркируются как представления, authoritative PDF — отдельно.

Проверить 1366×768, 1180×680 и стресс 1024×640, темы, keyboard navigation, F1, длинные имена/параметры. Измерять clicks, key actions, pointer travel с методикой и исходным журналом; разреженный replay не называть движением руки человека. Native G3: 10k строк/1 MiB p95 input-to-frame <=50 ms и first editable <=2 s; stress 100k/10 MiB без потери ввода. Browser timing и Rust unit microbench — только отдельные классы свидетельств.

### T6 — Visual Guide и native QA

Новый Guide создавать исключительно из запущенного Tauri, с source SHA, сборкой, ОС и исходными PNG. Старый CP09 Guide хранить как legacy, не подменять его подписи Tauri. Показать Open → Edit → Apply → Undo → Build → current PDF → Save/reopen → Export, ошибку, stale, Cancel, F1. Screenshot mockup не доказательство native поведения.

Win10 Pro — основной пользовательский стенд, macOS ARM — отдельная проверка. Существующие FlowBridge службы/каталоги/runner не менять. Реальные IME и 100/125/200% DPI проходят самостоятельно. Недоступные стенды помечать NOT_RUN, продолжая независимые доступные задачи.

### T7 — последующая научная очередь

После общего source/build контракта продолжить оставшиеся SC3, SC4–SC6; затем Asymptote → Typst/CeTZ. Дальнейшие домены: UML → BPMN → инженерия → химия/биология → анимация → остальное → данные последними. Наличие панелей будущих доменов в Tauri-ветке не меняет приоритетов и не означает их приёмку. Stable Scientific Studio 1.0 требует прежнего полного согласованного scope.

## 4. Пакеты для младших агентов

Пакеты подготовлены для независимых worktree от зафиксированного интеграционного SHA. В текущей сессии отсутствует доступный launcher субагентов; фактически запущенных агентов: 0. Не выдавать эти назначения за запущенные модели. При доступном launcher записать точные model/session/task IDs и base SHA в журнал ниже.

| ID | Предпочтительный исполнитель | Владение файлами | Результат и предел полномочий |
| --- | --- | --- | --- |
| J1 | младшая coding-модель | package.json/lock, frontend config и tests | dependency/build/typecheck; не менять IPC semantics или canonical source |
| J2 | младшая Rust-модель | src-tauri manifests, commands helpers/tests | native compile/IPC contracts; не менять core save/build policy без интегратора |
| J3 | младшая test-модель | scripts/qa_tauri_*, независимые test fixtures | negative source/UTF/Save/Undo/stale tests; не исправлять production одновременно с проверкой |
| J4 | младшая documentation/UI-модель | guide manifest, user help, capture plan | реальные Tauri screenshots, подписи и клики; не рисовать доказательства |
| R1 | отдельный reviewer | insights review records, без production write | review source/CI/logs/PNG/PDF, вопросы и доказанные находки |
| INT | основной исполнитель | AGENTS/архитектура/main integration, shared source/build | сложные решения, конфликтующие изменения, exact-SHA merge, final review |

Одна задача = цель, входы, разрешённые файлы, запрещённые изменения, команды тестов, артефакты, commit SHA. Один файл не принадлежит двум авторам одновременно. Субагенты не пушат в main и не создают release tags. Интегратор не принимает собственную проверку за независимого агента.

## 5. Коммиты, публикация и контрольные точки

Коммит после каждого содержательного пакета: план/решение; tags/интеграция; сборочные исправления; IPC/document vertical; scientific parity; guide/QA. Push выполнять после локальных доступных проверок и review diff, сохраняя failures отдельно. Не создавать пустые коммиты, не переписывать чужую историю.

После каждого пакета обновлять insights и краткий статус: что реализовано, что проверено, какой точный SHA, какие ограничения, одна следующая задача. Main может содержать явно помеченную development-интеграцию; это не разрешение на стабильный релиз. Для отката предпочтителен revert интеграционного коммита или checkout архивного тега, не force reset опубликованного main.
