# W3 — изолированное исправление Build для несохранённого рисунка (2026-11-10)

## Контекст и доказательства

- База: trusted main `2db4d5a1b798b8ac9bd7a43ef01f531b637090f0`.
- Physical Windows 10 Pro 22H2 x64 GUI START с локальной Mesa подтверждён владельцем; вся физическая W3-цепочка (6 жестов/F1/Undo/Save/Open/IME/GUI→XeLaTeX) НЕ ПРИНЯТА.
- Воспроизведённый владельцем симптом: клик по верхнему треугольнику ▶ не показывает результата. Ранее неизвестно, появляется ли нативный Save As за RDP-окном, продолжается ли TeX discovery, либо недоступен XeLaTeX. Гипотеза о Save As НЕ считается установленным физическим root cause.
- До изменения: `show_studio_toolbar -> build() -> save() -> save_as()` на scratch без `document.path`; Windows/macOS открывают нативный FileDialog. Реальный `build()` возвращает управление без запуска XeLaTeX при отмене сохранения. Статус отображается внизу GUI и мог быть заслонён панелью задач.

## Изменения кандидата

1. Новый встроенный `egui::Modal` «Сохранение перед сборкой» для любого несохранённого документа, когда доступен XeLaTeX и не занят worker. Никакого скрытого нативного диалога в пути scratch Build.
2. Пользователь явно вводит путь нового `.tex`, выбирает «Сохранить и собрать PDF» или «Отмена»; Escape тоже отменяет. Предложенный toolbar `file_field` не переиспользуется: он мог содержать путь, выбранный для Open.
3. При вводе пути проверяется существование целевого файла. Перезапись постороннего файла или symlink-цели без подтверждения не допускается по общему `typed_save_destination`. При ошибке диалог остаётся открытым и сообщает причину. Сохранение записывает исходный TeX через тот же Document API, затем вызывает обычный внешний XeLaTeX Build. Не вводится собственный TeX-рендерер.
4. В отдельном модуле есть unit/event тесты: существующий/alias путь запрещён; реальный egui click release создаёт только решение Save (не осуществляет запись самостоятельно); после сохранения сохраняются UTF-8, кириллица, CRLF и исходные байты.
5. Сохраняются TeX discovery, single-worker, cancel, source authority, общий Undo и feature freeze. Не меняются драйверы, система Windows, MiKTeX, runner и FlowBridge.

## 2026-11-10 — вторая итерация: видимая причина отказа Build

Проверка GUI-кода выявила отдельный риск: `build()` возвращает управление с сообщением только в нижней строке при незавершённом TeX discovery, отсутствии XeLaTeX в окружении GUI, уже выполняющейся сборке, ошибке сохранения или отсутствующем пути. Для Win10 RDP @1366×768 строку состояния может перекрывать панель задач. Добавлен контекстный предупреждающий текст **под верхней панелью**, только для блокирующих причин Build (`Сборка не начата:` и `Сборка уже выполняется:`). Ошибка среды GUI не приравнивается к ранее успешной CLI-сборке. Добавлен unit-тест фильтра предупреждений. При `Compiling with XeLaTeX` не показывается ложная ошибка. Временный статус не используется для физических PASS.

На первоначальном SHA `2b5350ca` завершились **PASS**: общий Rust CI Win/macOS/Linux, независимый D QA Win/macOS/Linux, N1 реальные XeLaTeX fixtures, Windows hosted HWND/F1, MiKTeX и шрифтовой контроль. Два GUI/packaging job `I61` и `N5` завершились failure **строго на source-tree lease** до GUI — непройденные по контракту, не функциональный регресс. После изменения предупреждения требуется новый exact-head CI, и до этого нельзя переносить старый PASS на новый SHA.
