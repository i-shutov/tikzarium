# TikZarium — локальный GUI/egui QA API v0 (проверяемый эксперимент)

**Цель:** заменить большую часть мышиных автотестов воспроизводимыми командами через JSON Lines и виртуальные кадры настоящих egui-компонентов. Это средство QA, а не публичный HTTP API. Создано как отдельный бинарник, основной GUI, Linux RC и внешний XeLaTeX не изменены.

## Два независимых слоя

- **Семантический:** отправляет операции непосредственно в уже используемые GUI \`tikz_authoring::Session\`, \`tikzarium_core::Document\` и общий каталог C. Проверяет инварианты: точные изменения .tex, CRLF/Unicode, ownership, библиотечные SourcePatch, выбор объекта, Undo и запрет перезаписи устаревшего исходника.
- **Виртуальная GUI-поверхность:** \`egui::Context::run(RawInput)\`, настоящий \`show_group_rail_observed\`, \`show_palette_observed\`, \`show_guide_frame_mode\`, Inspector, Library panel и F1. На входе размер окна в пикселях, DPI и события мыши/клавиатуры, на выходе фактические egui-Rect с именами элементов и координатами. Нет необходимости гадать, куда кликать.

Эти два слоя намеренно соединены одной \`Session\` и одним буфером исходника; тесты могут после \`input.drag\` получить \`state.snapshot\`, не создавая второй редактор или дополнительный PGF-рендерер.

## Запуск

Сначала соберите из **проверенного исходного SHA** в обычной среде разработчика:

\`\`\`sh
cargo run --locked -p tikzarium-app --bin tikzarium-qa-control -- --root <EXISTING_QA_DIRECTORY>
\`\`\`

Вход — одна JSON-команда в строке stdin, ответ — одна JSON-строка \`{"ok":true,"result":{...}}\` либо \`{"ok":false,"error":"..."}\`. Протокол автономный, **не слушает порт**. Каталог \`--root\` обязателен, запись файлов возможна только по явным операциям в рамках него. Другие пути, абсолютные адреса, выход по \`..\` и файловые симлинки запрещены.

Пример последовательности:

\`\`\`jsonl
{"op":"window.set","width":1366,"height":768,"dpi":1.0}
{"op":"layout.snapshot"}
{"op":"input.click","target":"group.geometry"}
{"op":"input.click","target":"tool.circle"}
{"op":"input.key","key":"F1","down":true}
{"op":"input.key","key":"F1","down":false}
{"op":"document.new","source":"\\documentclass{standalone}\n\\usepackage{tikz}\n\\begin{document}\n\\begin{tikzpicture}\n\\end{tikzpicture}\n\\end{document}\n"}
{"op":"tool.insert","tool":"circle"}
{"op":"state.snapshot"}
{"op":"authoring.undo"}
\`\`\`

\`layout.snapshot\` возвращает названные виджеты с фактическими прямоугольниками в **egui points** и пикселях (\`dpi\`), например \`group.geometry\`, \`tool.circle\`, \`guide.canvas\`, \`authoring.undo\`, \`dock.libraries\`, \`library.panel\`. Перед кликом запросите свежий layout: расположение действительно меняется при смене размера, DPI, вкладки и раскрытии палитры.

\`input.click\` принимает \`target\` из последнего layout либо \`pos: [x,y]\` в **пикселях**. \`input.pointer\` принимает \`pos\` и \`down\`, \`input.drag\` — \`from\` и \`to\`; \`input.key\` — \`key\`, \`down\` и модификаторы. \`input.text\` передаёт настоящий \`Event::Text\`. Операции \`tool.gesture\` отдельно принимают координаты в **сантиметрах**, а не пикселях, и создают source patch через C. Блокировки для ручных правок, сохранения и Undo сохраняются.

## API v0: реализованные действия

- Документ: \`document.new\`, \`document.open\`, \`document.save\`, \`document.save_as\`, \`source.replace\` (с revision lease).
- Шесть инструментов: \`tool.select\`, \`tool.insert\`, \`tool.gesture\`, \`object.select\`, \`parameter.set\`, \`parameter.apply\`, \`authoring.undo\`.
- C/N2/N3: \`library.connect\`, \`library.disconnect\`, \`help.search\`.
- Виртуальный egui: \`window.set\`, \`frame.run\`, \`layout.snapshot\`, \`input.click\`, \`input.pointer\`, \`input.drag\`, \`input.key\`, \`input.text\`, \`view.dock\`.
- Диагностика: \`api.describe\`, \`state.snapshot\`, явный \`ok/error\` без молчаливого результата.

**Не реализовано в v0:** прямое управление OS open/save-dialog, GPU, Windows/macOS viewport, VNC, реальный IME, проверка рендеринга шрифтов, и настоящий XeLaTeX/PDF из административного сеанса. Ни один headless PASS не засчитывается как физическая Windows 10/Windows Server GUI-приёмка или выпуск 1.0. Эти вертикали требуют отдельного реального тестирования.

## QA/dot

Запускать из GitHub/Codex/Work можно сериями команд JSONL, сохранять исходники, отчёты и минимальный воспроизводящий сценарий. Для каждого найденного регресса фиксировать Git SHA, входные JSONL, фактический \`layout.snapshot\`, ожидание/факт. Сначала hosted CI с \`cargo test --workspace\` и \`scripts/tests/test_qa_control_api.py\`, затем review, только после merge доверенного main — допустимая проверка на личном runner. На persistent Windows нельзя выполнять произвольный PR-код и нельзя отключать защиту MiKTeX/UAC.

### Условие перехода к следующей версии

Вынос действий \`TikzariumApp\` (включая настоящие File picker, Build/Cancel, Export PDF, page navigation и UI modal) в общий диспетчер без повторной реализации. До этого API v0 не должен заявлять стопроцентное покрытие всего GUI.

## CI source lease

Changed egui app source tree (test-only bin and `pub(crate)` observer visibility) requires an exact I61/N5 source-tree review, not weakening an old lease. New app/src Git tree: `51e214061aea24978b06130927bd889019f75654`. I61 real X11/full PDF and N5 packaged Linux are required to re-run on this exact tree, including their original font/PDF evidence. Hosted UI API tests are supplementary and do not replace those gates.

## Responsive virtual viewport check

Virtual panel widths now follow the logical viewport `width / dpi` rather than fixed pixels, so 200% DPI tests do not accidentally leave a 23-point canvas. QA independently checks the source and inspector panel rectangles as it resizes. This does not assert that actual Windows Desktop visual placement was tested.
