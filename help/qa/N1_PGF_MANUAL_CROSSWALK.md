## Global bounds and provenance

The 28 `default` fields in C07 are **`default_provenance="editor_preset"`**: they are convenient initial values generated by our UI and **must never be described as PGF/TikZ defaults**. `pgf_version_min="UNKNOWN"` is deliberate: the manual version `3.1.12` says what source was reviewed, not the earliest supported PGF release. `max_abs=10000.0`, units, `positive`, enumerations and fixed tool count are restrictions **of the initial inspector literal controls**, not restrictions on handwritten TikZ. Raw source must accept PGF coordinate expressions, macros, additional units and library-specific semantics without being silently rewritten. Values of GUI themes must not influence TeX/PDF.

## Help text issues passed to C / B

1. **Important editorial distinction:** `mode` in the node entry is an **editor-only choice**; it is not interpolated into `\node` syntax. The current explanation says it changes interpretation, but an explicit *“не ключ TikZ”* sentence in F1/inspector would prevent confusion (PR #39/issue #35 coordination, not a hard metadata failure).
2. **Limits should remain visibly labelled:** `pt/mm/cm/in`, `max_abs`, and decimal-only literal validation are UI generator limits; the actual TikZ language is richer. Keep this label beside parameter controls and in help. In particular, §14.6 also supports unitless `radius` and transformations.
3. **Node math is not sandboxed:** the catalog warning correctly identifies raw math; the runner's `-no-shell-escape` does not sandbox arbitrary TeX. For text-vs-math examples in the UI, show both `\node at (0,0) {A};` and `\node at (0,0) {$x^2$};`, marking the second user-supplied TeX.
4. **Pointer/preview fidelity:** TikZ transformations and node anchors may break naïve overlay predictions; exact XeLaTeX PDF is authoritative. There is no need for a CAS/scene solver to launch these six native commands.
